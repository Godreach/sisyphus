# AI 辅助构想：仓库生成 Pipeline + 构建错误诊断

状态：构想（未定案）
日期：2026-08-18
涉及 ADR：ADR-0015（凭据加密，API key 存储复用）、ADR-0013（构建日志，诊断数据源）、ADR-0006（Pipeline 数据模型，生成产物）、ADR-0020（Web UI，入口与编辑器集成）、ADR-0014（角色，谁能配谁能用）、ADR-0001（定义只存 Server 端）
现状：v1 骨架开发中（B1~B3 冲刺）。本构想**不进入当前冲刺实现**，待 v1 骨架收口后单独立项。

## 核心思想

在 Server 端引入**可选的**大模型（LLM）接入：全局 admin 在设置里填 provider 地址 + API key（复用 ADR-0015 加密机制），平台获得两项 AI 辅助能力：

1. **仓库 → Pipeline 草稿**：给定一个已绑 SCM 的项目，AI 读仓库结构 / 构建文件，产出一份草稿 Pipeline 定义，进混合式编辑器供人审改。
2. **构建错误诊断**：构建失败时，AI 读失败任务的日志，给出"为什么失败 + 怎么修"的归因建议，附在构建详情页。

关键定位：AI 是**辅助（copilot）不是执行者**——生成产物进编辑器供人确认、诊断是建议不是判定。绝不自动改 Pipeline、绝不自动重跑。AI 是纯增量、可关闭、缺省不启用；provider 挂了或超时只影响 AI 入口，构建照跑。

## 痛点拆解

两件事都是"读一大堆上下文 → 产出结构化判断"的重复劳动，正是 LLM 适配的形态：

1. **手搓 Pipeline 的冷启动成本**：新项目接进来，从"看 repo 里是 Rust / Node / Go 哪种、构建文件长啥样、该怎么编排阶段与任务"到能在编辑器里点出一条能跑的 Pipeline，是纯人力翻译。AI 把这步从"空白起手"降到"改一份草稿"。
2. **构建失败排障**：长日志里找"真正那行报错"是 CI 老用户的肌肉记忆、新用户的痛点。AI 读全量日志给出指向（缺依赖 / 标签不匹配 / checkout 凭据问题 / 编译错误在哪条），缩短"红构建 → 绿构建"的来回。

## 设计骨架

### 接入：全局配置 + 凭据复用

- `provider base_url` + `model` + `api_key` 进**全局配置**（与 SMTP 同级，ADR-0015 已定全局配置走同一套密钥文件加密、变更入审计）。
- **不立第二套加密机制**。api_key 写入只存密文、永不回读（同机密可见性原则）——UI 只能覆写、不能查看。
- 配置权限：**全局 admin**（ADR-0014）。未配置时 AI 入口灰显，不影响平台任何核心能力。
- 多 provider：v1 只做"单一全局 provider"（一套 `base_url + key + model + protocol`），不做 per-project 覆盖、不做多 key 轮换。协议格式支持 **OpenAI**（`/v1/chat/completions`）与 **Anthropic**（`/v1/messages`）两种——市面 provider 基本都兼容这两者之一，二选一即可接；`base_url` 可指本地 / 内网 endpoint（Ollama、vLLM、企业内部网关），这是"数据不出域"的合规路径——所以配置项是 `base_url + key + protocol` 而非写死某家 provider。

### 能力一：仓库 → Pipeline 草稿

触发点：项目页"生成 Pipeline"按钮（项目已绑 SCM；已配 SCM 凭据则更顺）。

流程：

1. Server 拉取仓库 HEAD 的目录树 + 关键构建文件（`Cargo.toml` / `package.json` / `go.mod` / `Makefile` / `Dockerfile` / …，受 token 上下文窗口限制做有选择读取）——读 repo 走的是已有 SCM 凭据与 checkout 能力，不新引机制。
2. 组装提示：仓库事实 + sisyphus 的 Pipeline 模型 schema（ADR-0006 三级结构 + 步骤仅 shell / checkout + 8 个内置变量 + when 受限表达式），约束 AI 只产合法结构。
3. AI 返回 Pipeline 定义 JSON → 过模型 schema 校验 → 作为**草稿**进混合式编辑器（ADR-0020），revision 不递增、不落库，直到用户点保存。
4. 产物是"半成品建议"，UI 显式标注 AI 生成、需人工确认；不自动触发构建。

护栏：

- AI 只产**结构化定义**，但 shell 步骤内容本身是自由文本——这是固有风险点（见下「风险与边界」）。
- 生成产物**必须经人保存**才进 DB / revision，AI 无任何写权限。

### 能力二：构建错误诊断

触发点：构建详情页，失败任务上的"AI 诊断"按钮（**按需触发，非自动**——每次失败都调 LLM 是成本与噪声）。

流程：

1. Server 拉该失败任务本次 attempt 的整份日志（ADR-0013 已有整份 REST 下载端点，同源数据）。
2. 裁剪入上下文：per-job 日志上限 50 MB 远超模型上下文窗口，需尾部截断 + 错误行聚焦策略。
3. 附带构建上下文：Pipeline 名、任务名、退出码、步骤边界、标签要求。
4. AI 返回结构化诊断：最可能原因（分类）+ 证据行引用 + 修复建议（改 Pipeline / 改 repo / 改 Agent 标签 / 补机密）。
5. 诊断结果挂在构建详情页该任务下，**只读建议**，不触发任何动作。

护栏：

- 诊断不判败、不改状态、不自动重跑——构建成败以退出码为准（ADR-0006），AI 的话只供人读。
- 诊断结果可缓存（per build + job + attempt），避免重复调用烧钱。
- 日志在落库前已在 Agent 侧脱敏（ADR-0015），喂给 AI 的天然是脱敏后版本——AI 不会看到机密原值。

## 风险与边界（必须写明）

- **生成产物的安全风险**：AI 生成的 shell 步骤是自由文本，可能包含危险命令（`rm -rf`、外发 `curl`）。平台已有 Agent 侧日志脱敏但**没有**步骤内容审计。对策：生成草稿进编辑器后人工审；v1 不做沙箱（ADR-0002 容器可选、宿主机默认），长期可加"AI 生成步骤的高危模式静态扫描"提示。
- **成本不可控**：LLM 按 token 计费，仓库大 / 日志长 → 单次调用成本飘。对策：上下文裁剪策略 + 按需触发（不自动）+ 可配全局月度 token 上限（软阈值，超限禁用 AI 入口、平台核心不受影响）。
- **不可靠性**：AI 诊断会错（幻觉一个不存在的依赖、把标签问题误判成编译问题）。对策：永远定位为"建议"，UI 措辞绝不暗示"权威结论"；诊断附证据行引用让人可核验。
- **凭据外流边界**：调用外部 LLM = 把仓库片段 / 日志发往第三方。这是**数据出域**决策，必须由全局 admin 明确知情配置（设置页写明"启用后仓库内容与构建日志将发送至 `<provider base_url>`"）。只发脱敏后日志、只发必要仓库文件，不发机密原值、不发 SCM 凭据。
- **离线 / 自托管模型**：`base_url` 指内网 endpoint 即"数据不出域"——这是合规路径，作为正向能力保留，不是事后补丁。

## 与现状的对齐 / 冲突

- **凭据存储复用 ADR-0015**：API key 走全局配置 + 密钥文件加密，不立第二机制。与"任务机密"是两回事——任务机密是项目级、任务声明引用、进 job spec 下发；AI key 是全局配置、平台自身调用、**永不下发 Agent**。两者不可混用。
- **诊断数据源即 ADR-0013 日志**：不新引日志通道，复用整份日志下载端点的同源数据；喂 AI 的是脱敏后版本（ADR-0015 Agent 侧脱敏在离机前完成，落库即是脱敏版，天然安全）。
- **生成产物进 ADR-0006 模型 + ADR-0020 编辑器**：AI 产的是合法 Pipeline 定义 JSON，进混合式编辑器作草稿；保存才落库 + revision 递增，与现有编辑历史机制无缝衔接。**不绕过编辑器直接写 DB**。
- **角色对齐 ADR-0014**：配置 = 全局 admin；使用（生成 / 诊断）= 项目 admin（编辑 Pipeline 权限）/ runner（看构建、触发诊断）。viewer 能看诊断结果但不能触发。
- **不冲突项**：AI 是纯增量、可关闭、缺省不启用；不碰调度、执行、Agent、产物、机密任何核心语义。provider 不可用时只影响 AI 入口，构建照跑。
- **审计与指标**：API key 变更入审计（同 SMTP，ADR-0015 已定"全局配置变更"入审计）；AI 调用本身 v1 不入审计（量可能大、非安全事件），仅旁路记可观测指标（调用次数 / 耗时 / 成败，ADR-0019 指标体系）。
