# 制品库与日志归档实施规划

状态：设计已确认，尚未实施。决策依据：[ADR-0026](../adr/0026-optional-s3-build-artifact-spaces.md)、[ADR-0027](../adr/0027-agent-local-live-logs-and-terminal-archive.md)。本文件描述目标行为与分阶段交付，不代表当前代码已经支持这些能力。

## 产品边界

- 一级“制品库”入口按当前用户可访问的项目聚合构建产物，按项目、Pipeline、构建、任务、attempt、产物集及目录浏览、过滤和下载。未配置 S3 时入口仍显示，但明确提示不可用。构建详情继续展示全部有权查看的产物，包括旧本地产物；若一个构建混有本地与 S3 产物，一级入口提示旧产物仅在构建详情可见。
- 产物空间按**构建**隔离。构建 `#1` 与 `#2` 不共享命名空间，不解析“最新”，不提供跨构建依赖或 OCI/Maven/npm/PyPI 协议。日志归档也不作为产物展示。
- 产物属项目。当前权限：viewer/runner/admin 可浏览与下载，项目 admin 可配置任务声明及删除；Agent 只能操作获派任务授权的清单。全局 admin 沿用隐含项目 admin 权限。将来重做角色模块时以集中权限策略替换这张矩阵，不把权限刻进对象 key。
- 未配置 S3 时，现有单文件任务上传、构建内下载和构建详情下载仍使用本地存储与原 30 天清理。配置 S3 后仅**新上传**使用 S3，默认永久保留；已有本地产物不搬迁、仍按旧规则清理。产物总保留期与日志总保留期解绑。

## 配置和 S3 契约

- 一个 Server 全局后端：endpoint、region、bucket、可选根前缀、access key、secret key、path-style 开关、可选 TLS CA 路径。部署者准备 bucket、账号、TLS、备份与容量；Server 不安装产品、不自动建 bucket。配置在重启时生效，Secret 不从普通配置 API 回显或写日志。
- endpoint 必须同时能由 Server、所有需传输的 Agent 和用户浏览器访问。首版不支持内外双 endpoint。启动验证配置完整性、凭据及 bucket 可访问性；显式“测试连接”验证小对象 PUT/HEAD/Range GET/DELETE、普通复制与 multipart 上传/复制，并清理探针。配置明确且无效时拒绝启动；运行期 S3 故障只影响相关传输与归档，不拖垮其它功能。
- 最低 API 契约：SigV4、预签名 PUT/GET、PUT/GET/HEAD/DELETE、Range GET、前缀列举、CopyObject、multipart create/upload part/complete/abort 和 UploadPartCopy。只承诺符合此契约并通过测试的后端，不声称所有标榜 S3 兼容的产品都可用。软件不强制判断是否真正自托管。
- 记录后端配置身份。旧对象不得被改变 endpoint/bucket/prefix 后的新配置误读：若已有引用而配置被替换，启动拒绝并要求恢复旧配置；移除 S3 配置可启动，但旧对象明确显示“后端未配置”。首版不做热切换、多后端管理或批量迁移工具。
- 产物和日志使用互不重叠的内部前缀；临时对象与最终对象再分开。bucket 生命周期不得自行删除 ready 产物或日志归档；Server 按自己的状态与保留期清理。数据库是唯一目录事实源，外部 PUT 不自动导入，外部 DELETE/改写须报告异常。

## 产物集协议

1. Pipeline 沿用任务级 `artifact_uploads: [{name, path}]` 与同构建 `artifact_downloads: [{job, name, path}]`。同任务上传名唯一，路径必须在 workspace 内；声明无需稳定 ID，运行时由 Server 分配产物集 ID。内部对象键包含构建、任务、attempt、产物集的稳定 ID，不直接使用用户提供的路径作为授权边界。
2. 步骤与缓存保存成功后，Agent 扫描声明的文件或目录，形成普通文件、空目录、相对路径、大小、SHA-256 和 Unix 可执行位清单。拒绝 symlink、junction、socket、device、FIFO、路径逃逸、Windows 保留设备名以及大小写折叠后冲突；不保留 owner、ACL、扩展属性或 mtime。相对路径统一 `/`，不支持 glob。一个声明生成一个产物集，默认最多 10,000 文件。
3. Server 校验清单和部署级限额：单文件默认 10 GiB、单任务一次发布合计默认 20 GiB；限制可配置。按清单为每个文件签发短期临时 key 上传许可，不给 Agent bucket/构建前缀的长期访问权。小于 100 MiB 单 PUT；更大文件 multipart，默认 64 MiB 分片、4 路并发、可重试分片。过期 pending 与未完成 multipart 由后台 abort/清理。
4. Agent 完成上传后提交清单和摘要；Server 从临时对象流式核验 SHA-256，再复制到从未签发 PUT 的最终 key，并校验最终对象。单次复制不超过 S3 CopyObject 限制；更大对象使用 multipart copy。清理临时对象后，数据库原子地将**整个产物集**标记 ready；pending/删除中对象不可见且不可签发下载 URL。重试复用同一 pending ID，ready 后重复完成请求幂等。完整性异常保留失败状态并清理临时内容，不发布半成品。
5. 依赖该产物集的任务只在 ready 后可派发。下载先进入 Agent staging，校验完整清单及每个文件 SHA-256，再将目标文件原子替换或将目录整体替换，不合并旧目录；同任务的下载目标不得相同或嵌套。失败、取消、超时 attempt 不上传；上传失败使该 attempt 失败，自动重试及 allow_failure 沿用现有语义。成功重跑产生独立 attempt 产物，旧成功任务仍沿用原成功 attempt。
6. 用户下载单文件时 Server 先按项目授权，再签发默认 5 分钟有效的 GET URL；浏览器使用普通导航下载，不承诺跨源 fetch/预览或整目录 ZIP。目录可浏览、文件可逐个下载。UI 展示大小、SHA-256、来源和可用状态；Server 在 ready 前严格哈希核验，平常读取仅检查存在/大小，管理员可按需深度校验。相同大小的外部篡改不保证每次浏览器直连下载时立即检出。

## 日志协议与状态

- Agent 将运行日志写在自己管理的持久缓冲区，而非构建脚本可控制或管理员工作区清理会触及的工作区。保留每个任务 attempt 的有序、带类型事件和 seq；本机先持久化再提供直播。只有用户查看时 Server 才从指定 seq 订阅 Agent，向多个浏览器复用一条上游订阅并经 SSE 回放/尾随；最后一名观看者离开则取消订阅。慢客户端不能阻塞任务，可重新按 seq 读取。Agent 离线时尚未归档的运行日志暂不可读。
- attempt 执行结束后封存日志。内部归档每约 4 MiB 原始事件构成独立 gzip 帧、组成一个对象，附带 `seq → 对象字节范围` 稀疏索引；格式不作为公开 API。Server 从本地文件 seek 或 S3 Range GET 读取归档，解码后仍从现有 SSE/日志接口提供历史与整份流式文本下载，不把整个日志拼入内存，也不向浏览器签发原始日志对象 URL。
- `log_archive_backend` 取 `local | s3`：无 S3 时只能 local；配置 S3 后默认 s3，也可选 local。终态归档不能完全关闭。S3 路径采用 Agent 预签名直传临时 key、Server 哈希校验、复制到最终 key、登记 ready；本地路径由 Agent 上传 Server 临时文件，Server 校验并原子改名。Server 不持续存储直播正文。
- 正常收尾：Agent 封存并报告最终 seq/大小/SHA-256，归档上传和 Server 确认完整后上报正式任务终态，延迟清理本地缓冲。短时间重试期间占用计算槽位；若仍失败，释放槽位、保留原执行结果、日志状态置待归档并后台重试，不触发构建重跑或 fail-fast。Server 确认前不自动淘汰缓冲；Agent 永久丢失时管理员可审计地标记日志永久丢失。迟到事件不能静默改写 ready 归档。
- 单任务原始日志上限默认 1 GiB，超限插截断标记而不判任务失败。Agent 缓冲总量默认 20 GiB，达到 90% 压力阈值停止领取新任务，运行中任务仍受单任务限制。待归档容量与错误显示在管理界面；强制删除未归档日志需要审计并置永久丢失状态。
- 日志总保留期默认 30 天，自 attempt 执行结束起算；查看与重试不延长。到期删除归档和索引，手动清理终态构建时立即删日志。旧 SQLite chunk 保持可读至其原保留期结束，不在启动时迁移。构建状态与日志状态独立。

## 删除、恢复与运维

- S3 产物空间默认永久保留，常规日志到期清理、Pipeline 删除和普通构建数据清理不删除它。仅项目 admin 可删除整个产物集或整个构建产物空间，不可删其中单文件；排队/运行中的构建不得清理。构建数据清理默认保留 S3 产物，可显式勾选同时删除；旧本地产物按旧规则清理。保留产物时留下来源项目、Pipeline、构建号、分支/commit、任务与 attempt 的最小快照。
- 删除先在 DB 标记 deleting，停止列举和签 URL，后台幂等删除对象，成功后移除正文元数据，失败重试并显示积压。项目删除先冻结授权与空间，确认后后台清理全部产物和日志；清完前保留项目 ID 与审计快照，避免无主对象。构建内已准备消费的产物被删应以明确错误失败。
- 提供只读一致性检查：ready 元数据指向缺失对象、对象大小/校验异常、未登记的 bucket 对象、删除/上传积压及待归档日志。深度哈希为显式管理操作，不持续扫描全部正文。备份和恢复须同时考虑 SQLite 与 bucket；恢复后先检查，首版不提供跨系统原子快照或自动修复。

## 分阶段实施与验收

1. **存储契约与配置**：增加可选 S3 配置、非破坏性启动校验、显式连接测试、后端身份记录、操作状态和对象键策略。先用符合最低契约的自托管后端做集成测试，并覆盖错误凭据、缺 bucket、网络中断与移除/误换配置。
2. **产物数据面**：扩展上传声明为文件/目录清单、运行时产物集/attempt 元数据、预签名 multipart、临时对象校验及最终复制；将删除和清理从当前本地路径代码移入存储后端接口。验证跨平台路径拒绝、上传重试/崩溃恢复、旧 URL 重放、10 GiB 分段及 10,000 文件边界。保留旧本地读取路径。
3. **调度和界面**：消费者 ready 门控、目录 staging 整体替换、项目权限、一级入口和构建详情混合后端呈现；测试从失败任务重跑、同名任务产物、运行中删除阻止、手动清理默认保留与异步删除失败。
4. **日志协议**：先引入 Agent 本地封存归档及 Server 本地归档后端，再增加按需订阅和 S3 归档；旧 SQLite 日志读取与新归档并行，待新链路端到端通过后停止持续写 SQLite。验证断线/重启按 seq 回放、无人查看、归档失败不改任务结果、容量压力、永久丢失标记、SSE 历史读取和大文件流式下载。
5. **运行与迁移收口**：拆分保留清理器，增加上传/复制/归档/删除积压指标、审计和一致性检查，更新配置样例、部署/备份文档与运维告警。核对旧 ADR 与现有 API 契约的变更，保持旧构建快照和旧本地对象可读直至到期。

首版不包含：包管理协议、跨构建产物解析、目录 ZIP 下载、浏览器上传/预览、多 S3 后端切换、自动旧数据迁移、按项目配额和 bucket 外部对象自动导入。
