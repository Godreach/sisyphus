# 项目库独立导航与新建流水线交互重设计

## Problem Statement

用户在跨项目流水线列表点击「新建流水线」后，被带到普通项目列表；选择项目后进入项目详情，还必须再次点击「新建流水线」才能输入名称并进入编辑器。创建动作退化成浏览导航，用户意图被打断，且容易误把项目列表的「新建项目」当作创建流水线的后续步骤。

项目列表目前没有独立的侧栏入口，只能通过上述创建动作间接访问，项目的浏览与管理缺少稳定、可发现的入口。

此外，创建入口未完整遵循项目管理员权限，编辑器首次加载同名定义可能进入普通编辑态，既有 upsert 保存语义不能保证新建操作不覆盖已有流水线。

## Solution

在侧栏新增「项目库」一级入口，将项目浏览管理与跨项目流水线操作分离；「新建流水线」在发起页面打开轻量对话框，收集所属项目与流水线名称后，直接进入混合式编辑器。首次保存成功才正式创建流水线。

导航顺序固定为「工作台 / 项目库 / 流水线 / 构建机」。项目库承载现有项目列表，不增加新的领域实体：「项目」仍是 Server 端顶层组织单元，「项目库」仅为项目集合页的产品名称。

核心动线：

- 项目浏览：侧栏「项目库」→ 项目列表 → 项目详情。
- 全局创建：侧栏「流水线」→「新建流水线」→ 在当前页选择项目并输入名称 →「创建并编辑」→ 编辑器草稿 →「保存并创建」。
- 项目内创建：项目详情或其流水线空态 →「新建流水线」→ 对话框自动带入并锁定项目，仅输入名称 →「创建并编辑」→ 同一编辑器草稿。

取消对话框留在原页面；编辑器提供明确的返回入口，回到发起创建的页面，恢复列表筛选与滚动位置，不强制经过项目详情。

## User Stories

1. 作为已登录用户，我希望侧栏始终提供「项目库」，以便直接查看我有权访问的项目。
2. 作为已登录用户，我希望一级导航顺序为「工作台 / 项目库 / 流水线 / 构建机」，以便稳定定位工作对象。
3. 作为项目浏览者，我希望项目库页面标题和集合层面包屑都使用「项目库」，以便确认自己所在的位置。
4. 作为项目浏览者，我希望项目库仅显示我可见的项目，以便不会看到无权访问的资源。
5. 作为项目浏览者，我希望继续搜索项目并点击项目进入详情，以便查看仓库、成员与项目内流水线。
6. 作为全局管理员，我希望在项目库使用「新建项目」，以便创建新的组织单元。
7. 作为普通用户，我希望项目库不展示无权执行的「新建项目」，以便不会走到失败的操作流程。
8. 作为项目管理员，我希望在全局流水线页面点击一次「新建流水线」就打开创建对话框，以便不必先浏览项目列表和项目详情。
9. 作为项目管理员，我希望创建对话框只有所属项目和流水线名称两个必要字段，以便快速进入编排。
10. 作为项目管理员，我希望项目选择器支持按项目名称搜索，以便在多个项目中快速定位目标。
11. 作为项目管理员，我希望选择器只包含我可管理的项目，以便不会选中只有查看或运行权限的项目。
12. 作为全局管理员，我希望所有项目都可用于创建流水线，以便沿用全局管理员隐含全部项目 admin 权限的规则。
13. 作为流水线创建者，我希望清晰看到当前选择的项目名称，以便不会把流水线建在错误的项目下。
14. 作为项目管理员，我希望从项目详情创建时自动带入且锁定项目，以便无需重复选择归属。
15. 作为项目管理员，我希望项目内流水线空态的创建入口使用相同交互，以便建立第一条流水线时无需学习另一套流程。
16. 作为 viewer 或 runner，我希望不显示项目内无权执行的创建入口，以便界面与实际权限一致。
17. 作为无任何可管理项目的普通用户，我希望页面明确提示「你暂无可创建流水线的项目」并提示联系项目管理员，以便知道为何不能创建。
18. 作为还没有项目的全局管理员，我希望创建对话框的空态提供前往新建项目的动作，以便知道如何准备流水线归属。
19. 作为流水线创建者，我希望项目清单加载时有明确的加载状态，以便不把等待误认为没有项目。
20. 作为流水线创建者，我希望项目清单加载失败时原地重试，以便不用离开流水线页面。
21. 作为流水线创建者，我希望缺少所属项目或流水线名称时不能继续，以便在进入编辑器前完成必要信息。
22. 作为流水线创建者，我希望名称的前后空白被去除，并就地显示名称校验错误，以便修正输入。
23. 作为流水线创建者，我希望同一项目中的同名流水线阻止创建，并允许修改名称或主动打开已有流水线，以便不会意外覆盖配置。
24. 作为流水线创建者，我希望不同项目允许使用相同流水线名称，以便沿用现有项目内标识规则。
25. 作为流水线创建者，我希望主按钮明确为「创建并编辑」，以便知道下一步会进入编排而不是立即完成保存。
26. 作为流水线创建者，我希望取消、关闭或返回时留在原列表且保留搜索、筛选与滚动位置，以便继续先前的工作。
27. 作为流水线创建者，我希望提交校验中防止重复点击，并在失败时保留输入，以便安全重试。
28. 作为流水线创建者，我希望编辑器明确显示「新建流水线」、项目名、流水线名和尚未保存的状态，以便不会把草稿误认为已创建资源。
29. 作为流水线创建者，我希望首次主操作为「保存并创建」，保存成功后切换为普通「保存」，以便理解草稿到正式定义的转变。
30. 作为流水线创建者，我希望未保存草稿不出现在流水线列表、不生成修订版本也不触发构建，以便创建边界清晰。
31. 作为流水线创建者，我希望已修改草稿在离开前得到确认提示，并可选择继续编辑，以便不丢失未保存配置。
32. 作为流水线创建者，我希望未修改草稿可以直接退出，以便不用确认无实际内容的离开。
33. 作为流水线创建者，我希望编辑器返回按钮和浏览器返回都尊重发起页面，以便不会被送到固定的项目详情页。
34. 作为流水线创建者，我希望刷新创建态链接仍能识别新建意图，且在刷新前提示可能丢失的未保存内容，以便不会误入同名定义编辑态。
35. 作为流水线创建者，我希望首次保存时即使其他人刚创建了同名流水线也不会覆盖对方配置，以便并发创建安全。
36. 作为流水线创建者，我希望项目被删除、权限变化或网络失败时保留可恢复的输入并明确提示原因，以便决定修改、重试或返回。
37. 作为双语用户，我希望中文「项目库」与英文「Projects」及所有新建态文案完整对应，以便切换语言后导航与操作仍清晰。
38. 作为键盘用户，我希望创建对话框有焦点约束、可搜索选择项目、按 Enter 提交、按 Escape 关闭，并在关闭后恢复入口焦点，以便完成同样的创建流程。
39. 作为平板或使用折叠导航的用户，我希望抽屉导航也包含项目库且对话框内容不溢出，以便在现有响应式范围内使用。

## Implementation Decisions

- 修改应用外壳导航、列表页创建入口、项目详情创建入口、创建对话框、混合式编辑器新建态和双语文案。保留现有组件库、主题、侧栏宽度与列表视觉约定。
- 「项目库」只用于集合入口、集合页标题和面包屑的集合层级；领域词汇、单个项目详情、「新建项目」、项目名称字段、API 资源名和数据模型继续使用「项目 / Project」。英文集合名称使用「Projects」。
- 项目库对所有已登录用户可达，列表继续遵循项目可见性过滤；「新建项目」仅全局管理员可见。
- 导航高亮按资源归属固定：项目列表和项目详情高亮「项目库」；跨项目流水线列表、流水线编辑器、构建列表和构建详情高亮「流水线」；构建机列表和详情高亮「构建机」。编辑器从何处进入不改变高亮规则，返回动作单独承载来源。
- 全局和项目内创建共用同一个对话框及名称校验行为，不另建选择项目页面。全局模式可选择项目，项目内模式展示只读项目名称。
- 全局创建权限取决于用户是否至少管理一个项目，而不是只判断其全局管理员身份。普通用户仅为 viewer/runner 且无可管理项目时隐藏全局创建按钮并显示无创建权限说明。全局管理员即使项目数为零也保留创建入口，以便展示前往新建项目的空态。
- 为既有项目清单 GET 增加可选查询参数 `permission=admin`，由服务端沿用现有权限 policy 过滤并按项目名排序；无参数行为不变。全局管理员返回全部项目，普通用户只返回自身为项目 admin 的项目。不通过逐项目读取成员或 SCM 凭据端点探测权限，不将失败当作空清单。
- 创建权限查询加载期间不提供可提交的创建操作；失败时展示可重试状态而不是权限不足说明。项目内入口遵循同一服务端权限结果。
- 已有项目清单创建项目的 `create=1` 语义保持独立。流水线全局创建采用流水线页的 `create=1` 表示打开对话框；关闭移除该标记而保留其他查询参数；创建确认后不得留下项目列表中间历史记录。
- 全局模式初始项目为空，要求明确选择；不隐式将当前多项目筛选、最近浏览项目或流水线行所在项目当成创建归属。项目内模式固定使用当前项目。
- 名称去除前后空白后校验必填，遵循现有模型合法性规则；拒绝无法作为单一 URL 路径段的分隔符、控制字符及保留路径名。不额外限定为英文名称，不改变已存在名称的读取兼容性。名称错误就地显示在字段下方。
- 「创建并编辑」先校验归属和名称并通过既有定义 GET 检查同名资源；存在则留在对话框展示「该项目已存在同名流水线」，提供修改名称或主动打开已有流水线。检查失败不能放行，不将所有 404 都视为可创建：须确认所选项目仍存在且可管理。
- 定义 GET 仅为用户反馈预检，不能作为并发保护。为定义 PUT 增加可选 `If-None-Match: *` 首次创建前置条件：首次创建必须在同一服务端原子操作内确认资源不存在；已存在返回 412 且不修改定义、不新增修订版本。无该头的普通编辑保存保留现有行为。同步 API 文档、客户端与 mock 契约；无需新领域实体或新建空流水线记录。
- 沿用现有项目下流水线编辑器路由。创建入口带显式新建模式标记，避免进入编辑器后静默加载同名流水线成为普通编辑态。新建模式加载发现同名定义时仍需阻止编辑覆盖，并让用户主动选择修改名称或打开已有资源。
- 草稿只在前端内存中，进入编辑器不发写请求。首次保存携带上述前置条件；成功创建修订版本 1，清除新建模式标记、更新已保存基线并切换普通编辑态。保存失败保留草稿，不误显示已创建。
- 首次保存遇到 412 时保留用户草稿并提示同名冲突，不自动重试为普通 upsert，也不自动覆盖。用户可返回修改名称或主动打开已有流水线；离开仍遵循未保存确认。
- 返回来源保存为同源应用内位置，保留发起列表的查询参数、视图模式和滚动位置；显式返回按钮不依赖当前面包屑。来源无效或直接打开链接时回退至流水线列表，禁止外部或认证页面作为返回目标。
- 创建对话框关闭恢复触发元素焦点。浏览器后退关闭对话框而不绕行项目页；再次打开默认清空名称与校验错误。确认进入编辑器后，首次浏览器返回直接回到发起页面，不重新打开已完成的创建对话框。
- 新建编辑器脏状态以用户可编辑定义与加载/成功保存基线比较，而非每次点击都视为修改。路由离开可选择留在编辑器或放弃；浏览器刷新/关页使用浏览器原生未保存提示。不承诺刷新后恢复草稿内容。
- 前往「新建项目」属于显式切换任务：在项目库打开既有新建项目流程，不嵌套创建弹窗、不自动创建流水线、不自动跳编辑器。项目创建完成后，用户通过流水线创建入口继续。
- 桌面和平板 768px 及以上满足 ADR-0023；沿用既有窄屏抽屉入口并同步四项导航，不扩大为完整手机适配。对话框采用现有 Naive UI 组件与图标体系，保证中英文文本和控制状态不改变布局尺寸或溢出。

## Testing Decisions

- 主测试边界是用户可观察的导航与创建流程：从应用侧栏/列表上的真实入口，操作创建对话框，进入编辑器并首次保存。测试 DOM、当前 URL、返回位置、可见错误与 HTTP 请求/响应结果；不测试组件私有状态、内部函数调用顺序或抽象结构。
- 优先沿用现有应用外壳、项目列表、项目详情、流水线列表和编辑器的页面级测试模式：Vue Test Utils、内存路由、Pinia 和既有 API mock。补充一条组合真实路由页面的创建闭环测试，避免仅在壳层断言跳转到占位组件就宣告动线通过。
- 导航覆盖已登录用户四项导航及固定顺序、项目库可达、资源层级高亮、折叠抽屉、未登录无壳，以及中文/英文标题与集合层面包屑。
- 权限使用混合角色数据：同一用户在不同项目为 viewer、runner、admin，以及全局管理员。验证全局按钮、项目内按钮、项目选项、空态、新建项目按钮和直接调用接口的权限结果一致。
- 创建成功覆盖全局入口、项目详情入口与项目内空态入口；验证不会经过项目列表中间页面、不发送预创建写请求、项目内归属锁定、第一次保存修订版本为 1、后续普通保存不携带首次创建前置条件。
- 输入和错误覆盖空值、首尾空白、非法路径名称、中文名称、同项目重名、不同项目同名、权限查询失败重试、同名预检失败、重复点击、创建过程中项目删除或权限撤销以及保存失败后草稿保留。
- 返回覆盖对话框取消/关闭/Escape/浏览器返回、编辑器显式返回和浏览器返回、列表查询/筛选/视图/滚动恢复、无有效来源的回退，以及来源值不能导致外部跳转。
- 未保存覆盖未修改草稿直接离开、已修改草稿拒绝离开和确认放弃、首次保存失败仍提示、首次保存成功后清除脏状态，以及新建模式链接刷新后不静默进入已有定义编辑态。
- 服务端使用既有 REST 权限契约测试验证 `permission=admin` 过滤及无参数兼容行为。用两名有权限的调用者并发提交同名首次保存，断言仅一个成功、另一个 412、原定义与修订历史未被覆盖；不能仅断言前端出现冲突提示。
- 客户端与 mock 契约测试覆盖条件首次保存的请求头、412 错误语义和正常编辑 upsert 兼容性。复用现有定义读写/422/404/权限测试先例，不增加为测试专设的业务接口。
- 对创建对话框进行键盘焦点、Enter/Escape 和关闭后焦点恢复检查；在桌面和平板、中英文与现有主题下做视觉核验。
- 测试边界待用户确认后发布 issue；这份草稿未授权开始实现。

## Out of Scope

- 不在生成 spec 阶段修改产品代码、提交实现或调整现有未提交工作。
- 不重做项目列表、项目详情、流水线列表或编辑器的整体视觉布局。
- 不新增组织、团队、项目组、项目层级、代码库实体或项目移动能力。
- 不增加模板、复制流水线、AI 生成、流水线导入或独立多步创建页面。
- 不将仓库 URL、分支、凭据、成员、阶段和任务配置放入创建对话框。
- 不实现持久化草稿、刷新后恢复草稿、自动保存或跨设备草稿同步。
- 不改变构建执行、触发器、调度、普通编辑修订版本或并发编辑策略；仅首次创建增加不覆盖保护。
- 不扩展权限体系或普通用户创建项目权限。
- 不要求完整手机适配，不调整侧栏宽度、主题偏好或现有列表间距等无关改动。

## Further Notes

- ADR-0014 的项目三级权限和全局管理员隐含全部项目 admin 权限保持不变；ADR-0006 的 Server 端定义与修订版本语义保持不变；ADR-0020 的混合式编辑器保留。
- 本规格对现有三项侧栏导航及「项目入口收编至流水线创建」的实现约定作明确调整：增加项目库独立一级入口。集合名称不替换 CONTEXT 中的「项目」领域术语。
- ADR-0023 曾要求编辑器只改视觉、保持混合交互逻辑；本规格明确允许与创建直接相关的新建态、返回和未保存确认增量，不重做编排交互。实现时应按现有文档约定增补决策记录说明导航和创建增量，不静默改写旧 ADR。
- 当前项目清单只提供可见性过滤而不提供管理权限筛选；定义保存是无条件 upsert，响应修订版本只能在写入后发现异常。因此权限过滤与条件首次创建是本规格的必要契约增量，不能用纯前端预检宣称满足安全验收。
- GitHub Issues 是规格的正式记录位置，发布时使用 `ready-for-agent` 标签，无需额外 triage。仓库内此文档为发布前可评审草稿。
