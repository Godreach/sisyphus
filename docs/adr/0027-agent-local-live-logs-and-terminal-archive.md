# 0027 - Agent 本地实时日志与任务终态归档

状态：已接受

## 决策

任务运行期间，日志正文仅保存在 Agent 管理的持久本地缓冲中；用户打开日志时，Server 才按任务 attempt 和 seq 向 Agent 订阅回放与尾随，并通过现有 SSE 接口转发，不持续保存直播正文。每次任务 attempt 结束后，Agent 封存带类型的日志事件并上传归档；未配置 S3 时归档到 Server 本地数据目录，配置 S3 时默认直传 S3，也可显式选择本地后端。终态归档不可完全关闭。Server 保存定位、完整性、稀疏索引和独立归档状态；日志不进入制品库，默认从 attempt 执行结束起保留 30 天。

正常路径先完成并确认归档，再正式上报任务终态。若即时重试后归档仍失败，释放计算槽位、保留原任务执行结果并标记待归档，由 Agent 后台重试；未经 Server 确认不得删除本地缓冲。Agent 永久失联可能导致未归档日志不可恢复，必须显式显示丢失状态，不能伪称归档成功。运行中 Agent 离线时按需直播暂不可用。

## 理由与取舍

现有逐事件压缩并写入 SQLite 的模式便于去重、范围读取和 SSE 回放，却会随着数百 MiB 日志形成大量数据库写入与正文存储。Agent 本地顺序写与终态单对象归档避免持续向 Server 传输无人查看的日志，也把执行结果和日志可用性分开；代价是直播依赖 Agent 在线、需要独立归档重试与容量保护，并须让旧 SQLite 日志可继续读取至原保留期结束。
