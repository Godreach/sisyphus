# 0015 - 任务机密与审计日志：密钥文件加密 + env 注入 + Agent 侧脱敏 + 全局 admin 审计

日期：2026-08-15
状态：已接受

## 背景

pipeline 执行需要凭据类敏感值（SCM 访问、推送 registry 等），ADR-0014 留下占位：机密管理归项目 admin、值永不可回读。硬约束：单二进制零依赖部署（ADR-0010，无 OS 钥匙串可用）、SQLite 落库（ADR-0004）、任务规格经 gRPC 通道下发且默认明文（ADR-0007）、日志采集链路已定（ADR-0013）、角色三档已定（ADR-0014）。盘问过程见 [wayfinder 票 #20](https://github.com/Godreach/sisyphus/issues/20)。

## 决策

**存储加密**

- 主密钥文件：首次启动自动生成 32 字节随机 key 文件（权限 0600，落数据目录，路径可经 config 改到其它卷）；无启动口令、无 OS 钥匙串。
- 值加密：XChaCha20-Poly1305（RustCrypto `chacha20poly1305` crate，纯 Rust、无 AES 硬件依赖、192 位随机 nonce），DB 存「版本字节 + nonce + 密文」。
- 防护边界：防「DB 文件/备份单独泄露」；数据目录整体失守（含密钥文件）无解，同机 root 不防--写入威胁模型文档。
- web UI 配置的全局 SMTP 密码走同一套加密，不立第二机制；密钥轮换 v1 不做（版本字节留口子）。

**解密与下发**

- Server 解密后，值随任务规格（job spec）经 gRPC 通道下发，与 Agent token 同级同通道。
- 不为带机密的任务强制 TLS：威胁模型与 token 一致（token 本就明文过通道）；文档写明跨公网必须 TLS。

**注入机制**

- 任务级声明 `secrets: [NAME, …]`，Agent 执行前按名注入进程 env（GitHub Actions 形态）；文件挂载为 v2 候选。
- `${}` 插值禁止解析机密值（防进命令串/进程列表/日志回显）；任务 env 键与机密名冲突 = 保存时校验报错。
- 可见性：项目 admin 管理（建/覆写/删），值只写不读、仅可列名；viewer/runner 不可见（连名都不列）。
- 构建引用了不存在的名 = 任务立刻失败，错误信息点名缺失项。
- 构建快照只存任务声明的机密名列表，不存值（值永不进快照 JSON）。

**SCM checkout 凭据**

- 项目级特殊凭据（项目设置存用户名 + 密码/token），checkout 步骤自动使用，不进任务 env、无需手动引用；Server 解密后随 job spec 的 checkout 节点下发，Agent 仅经 GIT_ASKPASS 等凭据助手机制递给 git/svn 子进程，永不上命令行。
- v1 凭据类型仅用户名+密码/token（覆盖 http[s] 的 git/svn）；ssh 私钥 v2。

**日志脱敏**

- Agent 侧精确字面量脱敏：本任务注入的机密值（含 checkout 凭据）在输出块离机前替换为 `***`；断线缓冲、补传、Server 落库（ADR-0013 链路）全部是脱敏后版本。
- 不做变形匹配（base64/截断绕过防不住，文档写明），对标 GitHub Actions 内置脱敏的同等承诺。

**审计日志**

- 入审计：登录成功/失败、登出；用户建/禁、管理员代办重置密码、PAT 建/销；Agent 建立 + 注册码签发、token 吊销；项目建/删；成员角色变更；机密建/覆写/删（只记名+操作人+时间，永不记值）；全局配置变更（SMTP、注册开关等）。
- 不入审计：构建触发/取消/重跑（构建记录已带操作人）、pipeline 保存（revision 历史已记操作人与时间）--避免双重记账。
- 保留期永久（量小）；防篡改 v1 不做哈希链/外部锚定（单机 SQLite 无独立可信存储，能改审计表的人也能重算链）--普通表 + 代码层禁 UPDATE/DELETE，真防篡改走外部日志外送（v2 候选）。
- 可见性：仅全局 admin 的审计页（REST + UI，按时间/用户/项目/事件类型过滤）；v1 不给项目 admin 项目域审计视图。

## 理由

- **密钥文件而非口令/钥匙串**：口令解锁破坏「换二进制即重启」的升级承诺（ADR-0010 发布节奏）；OS 钥匙串在 Linux 全矩阵无统一可用面；密钥文件是零依赖下「防 DB 单独泄露」的最简可行解，路径可配置到独立卷即获得合理的运维纵深。
- **XChaCha20-Poly1305 而非 AES-GCM**：纯 Rust 无 C 依赖（6 目标交叉编译，同 ADR-0014 选 argon2 的逻辑），192 位 nonce 免 nonce 管理重用风险。
  > 修订：此「纯 Rust 无 C 依赖」立场经 [ADR-0022](0022-smtp-tls-via-ring-exception.md) 划定边界——仅适用于机密值加密（DB 落库的 SMTP 密码、任务机密、SCM 凭据仍走 chacha20poly1305）；SMTP 传输 TLS 经 ring（含 C/asm），无纯 Rust 替代。
- **注入只走 env 一条路**：文件挂载/网络注入都是更大的暴露面；env 是 shell 步骤的原生消费形态，也是脱敏面最小的形态（值清单确定）。
- **checkout 凭据独立于任务机密**：SCM 访问是每个项目都需要的默认能力，不该强迫每个任务手工引用；独立形态让它不进 env、天然不参与 `${}`，暴露面小于把 SCM 凭据当普通机密用。
- **脱敏放 Agent 侧**：值此刻就在 Agent 内存里，替换成本最低；离机前完成则缓冲/补传/落库全链路免信任。
- **审计聚焦安全事件**：构建与编辑已有天然的操作人记录（快照/revision 机制），重复入审计只添噪声；永久保留在事件量小（管理动作稀疏）时成本可忽略。
- **不做防篡改链**：单点上自证清白无意义，写明威胁模型比假安全诚实。

## 后果

- server 侧新增 secrets 模块职责（加密/解密/管理 REST）；机密、审计两张表与项目表 SCM 凭据字段随首个迁移批次进 SQLite；proto 的 job spec 增机密值清单与 checkout 凭据字段（仅加字段，ADR-0007 演进规则内）。
- Agent runner 新增 env 注入与输出脱敏钩子；checkout 执行器凭据走 ASKPASS 机制。
- 解锁下游：#11 SCM 集成层（凭据形态与注入点已定）、#15 web UI（机密管理页 + 审计页入信息架构）。
- v2 候选清单：文件挂载注入、ssh 私钥凭据类型、密钥轮换、防篡改审计链/外部日志外送、项目域审计视图。
