# 0020 - Web UI 信息架构与混合式编辑器

日期：2026-08-15
状态：已接受

## 背景

票 #15：web UI 的信息架构（导航、项目页、pipeline 编辑页、构建详情页、agent 管理页）长什么样？用一次性原型验证三个问题：可视化 pipeline 编辑器的交互形态（画布拖拽 vs 结构化表单+预览）、中文/英文双语布局、初始化引导流程。

原型（12 页 + 三编辑器变体，zh/en 双语，headless Chrome 冒烟全绿）落在 `prototype/web-ui-ia` 分支，`web/README.md` 有运行说明；三变体经底部悬浮条切换对比后人工裁定。

## 决策

### 编辑器交互形态：混合式（变体 C）

**左侧派生式只读拓扑轨道 + 右侧结构化属性表单**：

- 轨道：阶段=列、任务=缩略 chip（状态色边、重试/allow-failure 角标），点击导航右侧表单；**布局由数据派生，不可手拖**，无画布坐标。
- 表单：选中任务的全部属性显式字段（标签、执行环境 image、when、重试/超时、机密引用、产物/缓存、步骤列表）；任务/参数/环境变量页签并存。

不采用 A（Vue Flow 全画布）与 B（纯表单）：

- v1 执行模型是阶段串行+阶段内并行（ADR-0006，无 DAG），画布的自由拖拽/连线没有承接对象，空间自由度是伪需求；属性藏抽屉、宽表单在画布上反而局促。
- 纯表单信息密度最高但丢失全局拓扑感，长 pipeline 要靠来回点补心智。
- 轨道花小成本保住全局感，布局永远由数据派生：省一个画布坐标存储字段，省一整类对齐 bug。

### 对 ADR-0003 的修正

Vue 3 + TS + Vite + vue-i18n v11 不变。**Vue Flow 从"编辑器基础"降级为"可选依赖"**：编辑器不再基于画布。若后续页面（如构建详情拓扑视图）需要再引入，届时无消费者则移除。锁版本 + fork 兜底的社区依赖风险随之降级。

### 信息架构（12 页定稿）

- 侧栏：概览 / 项目 / Agent / 管理组（机密·审计日志·Agent 升级·用户）；底部 zh/EN 即时切换。
- 概览：stat 卡 + 事实型警示态（ADR-0019：离线 Agent、无匹配任务、磁盘告警）+ 最近构建。
- 项目页：列表 + 新建（测试连接不阻塞保存、ls-remote 分支预填、SCM 凭据提示，ADR-0016）。
- 构建详情：阶段/任务卡（排队任务显示缺失标签等待态，ADR-0008）、SSE 日志流（步骤生命周期+输出块交织，ADR-0013）、产物下载；**加面包屑（项目 > pipeline > 构建号）**--原型唯一 IA 修正。
- Agent：列表四态（在线/离线/排空/版本不兼容，ADR-0017）+ 详情（系统/自定义标签分区、槽位、磁盘三口径、工作区/缓存手动清理）。
- 管理四页：机密（只记名不记值）、审计（仅安全事件）、Agent 升级（包上传、全量/单台、排空状态列）、用户/PAT（创建时明文一次）。
- 初始化引导：三步各自可跳过，均带 CLI 等价提示（ADR-0010）。

### 双语布局

vue-i18n v11、zh 为源语言、en 全量对译；原型验证全部页面双语即时切换无布局炸裂，表单标签/按钮按最长语言设计。

## 后果

- `sisyphus-model`（ADR-0009）的 TS 类型生成是表单/轨道的共同数据源，前端不重复定义 Pipeline 类型。
- 编辑器无需画布交互后，无障碍与键盘可达性成为可达成目标。
- vue-i18n 双语对账脚本（zh/en catalog CI 校验）仍是待办（迷雾：前端工程化票）。
- 原型分支 `prototype/web-ui-ia` 为一次性产物，保留作视觉参照，不合入 main；正式实现时以本 ADR 为准重写。
