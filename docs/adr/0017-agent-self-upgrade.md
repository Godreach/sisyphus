# 0017 - Agent 自升级机制：Server 分发、排空替换、失败退回

日期：2026-08-15
状态：已接受

## 背景

ADR-0010 已定发布策略（同版本成对发布、Server 先升、兼容窗口 N-1、升级=替换二进制重启），但只覆盖"手动替换"路径；ADR-0007 已定通道与 proto 演进规则；ADR-0009 在 Agent 侧预留 `upgrader/` 模块。本 ADR 定 Agent 升级机制本身：包如何到 Agent、升级时运行中任务如何处置、自替换与失败回退、窗口外 Agent 的精确行为。盘问过程见 [wayfinder 票 #18](https://github.com/Godreach/sisyphus/issues/18)。

## 决策

### 机制总形

- **Server 分发自升级为主，手动替换永远兜底**：管理员上传 agent 发行包到 Server，升级指令经既有 gRPC 通道下发，Agent 自行下载、校验、替换二进制并重启。配置/token 独立于二进制存放（ADR-0010 数据目录约定），任何自升级失败都退化为「手动替换二进制重启」这条 ADR-0010 原生路径。

### 包的分发链路

- **v1 仅管理员上传**（不自动拉 GitHub Releases，v2 候选）：web UI 上传、支持一次多包，按 ADR-0010 文件名规范自动识别版本与目标三元组；包文件存 data-dir、记 sha256。上传时校验版本在兼容窗口内（≥ N-1 且 ≤ Server 版本），窗外拒收。
- **包下载走 REST HTTP 端点**（agent token 鉴权），与产物上传同模式（ADR-0007：大文件不走 gRPC 流）。下载后 sha256 校验不过即弃、保持旧版本继续跑。

### 触发与排空

- **管理员手动触发**，全量 + 单台两种粒度；升级指令持久化，离线 Agent 重连后补发（与取消指令同机制）。不做自动强制升级、不做灰度分批。
- **无限排空**：收到升级指令即停接新任务，运行中任务全部到终态后才执行替换，不设超时；管理员等不及可取消任务解锁。调度层呈现「在线但不可派发」（区别于离线），UI 可见「等待任务完成」状态。

### 自替换与回退

- **Agent 自管 spawn**（被 ADR-0010「v1 无内置服务化」强制，Agent 不能假设有 systemd/NSSM 替它重启）：新二进制写临时文件 -> 原子换入（Unix rename 覆盖；Windows 先改名运行中的 exe 再写入新文件）-> 旧二进制保留为 `.old` -> spawn 新进程（继承参数与环境）-> 旧进程退出。任何一步失败：保持旧版本、上报错误、继续跑。
- **连续 3 次启动失败自动退回 `.old`**：退回后旧版本连回 Server 并上报失败原因。「回滚」不设专门机制——Server 保留全部窗口内已上传包，对任意包再发升级指令即是回滚（窗口内降级免费：Agent 无持久 schema，token/工作区/缓存不受影响）。

### 版本窗口的精确化（补齐 ADR-0010 边角）

- Agent 过新（> Server）：维持 ADR-0010「启动即拒连并明确报错」。
- Agent 过旧（< N-1）：**任务面拒连、升级面保留**——不派发任务，UI 显示「版本不兼容」而非「离线」，Agent 侧退避重试并写明日志；但版本握手、升级指令、包下载始终开放。窗口滑动（Server 升级把一批 Agent 瞬间推出窗外）不断掉它们的自升级通道；自动退回 `.old` 造出的窗外版本同理可救，无需人工上机。

## 理由

- 自升级 vs 纯手动：~100 台规模纯手动是明确痛点；更隐蔽的是 N-1 窗口让「不升级也能跑」成为常态，版本两级分化反是手动模式的真实风险。
- 无限排空：N-1 窗口意味着升级无紧急性，不存在「必须现在换」的理由；超时参数是伪需求，管理员可取消任务解锁。
- 任务面拒连、升级面保留：全面拒连会让窗口每次滑动都产生一批只能 ssh 上去救的机器——恰好是自升级要消灭的场景。
- 仅上传不自动拉：部署画像默认明文内网（ADR-0007），自动拉 Releases 引入外网可达/代理/token 三重配置面，v1 不值。

## 后果

- proto 新增：握手带版本号（双方版本互见）、升级指令、升级状态上报（仅加字段演进，ADR-0007）。
- Server 新增存储：已上传包清单（版本/目标/sha256）与持久化升级指令；包文件占 data-dir 磁盘，UI 提供旧包删除。
- 调度层新增「排空中」状态（在线但不可派发）；Agent 侧上报升级阶段（等待任务完成/下载中/换入中/启动失败退回中）。
- Agent `upgrader/` 模块（ADR-0009 预留）承载下载/校验/换入/spawn/失败计数与退回；token 落盘位置独立于二进制安装路径。
- web UI 新增面：agent 包上传与窗口校验、全量/单台升级操作、各 Agent 当前版本与升级进度——进 #15 信息架构。
