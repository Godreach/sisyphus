# 0024 - 前端契约 mock 开发模式

日期：2026-08-29
状态：已接受

## 背景

web 产品化（spec #100）先行于后端完建：后端仅实现约一半端点且无可演示数据，前端开发与设计定稿被数据卡死。备选路径有二：等后端（串行空转）、真后端 + seed（解决不了未实现端点）。票 #99 期间的纪律是「就近填充、缺显示 —」，产品化阶段该纪律会导致页面信息密度打折、后端阶段二次返工。

## 决策

引入 MSW（Mock Service Worker）作为**网络层契约 mock**，建立单一事实源：

- **契约即类型**：handlers 严格按前端 `api` 层类型定义（对齐 ADR-0005 REST 契约与后端 DTO 形态）实现；前端开发只依赖契约，不依赖后端进程。
- **单一缝**：同一套 handlers/fixtures 同时供 dev worker（`VITE_ENABLE_MOCK=1` 切换，关闭走 proxy 连真后端）与 vitest node 模式；组件挂载测试经真实 http client 打 MSW，取代逐 spec 手写 fetch mock。
- **handler 生命周期 = 契约测试与显式 mock 开发**：生产构建始终关闭 MSW；后端就绪后，handler 仅保留给隔离前端测试及显式启用的 mock 开发模式，并通过客户端/mock 契约测试与真实 API 对账，不作为默认开发路径或第二套业务实现。
- **契约先行**：前端发现后端缺失的端点/字段时，在契约票中定义 URL/请求/响应形态，mock 先行，后端照单实现——契约缺口不再以「—」就近填充掩盖。
- **fixture 纪律**：规模接近真实（验证分页/密度/筛选）、覆盖全状态矩阵（含空态/错误态），动态模拟构建生命周期（SSE 推送），使 mock 环境可直接作演示与设计验收。

## 后果

- 前端与后端解耦为**契约依赖**，两者可完全并行；契约票成为前后端的接口冻结点。
- 测试数据与开发数据合一，消灭双份 fixture 的漂移风险。
- smoke（构建产物面）与截图对照缝不受影响；MSW 不进构建产物。
- 风险：handlers 与后端真实实现漂移——由客户端/mock 契约测试、OpenAPI snapshot 和服务端集成测试对账抑制；新增或变更 REST 契约须同步三者。
