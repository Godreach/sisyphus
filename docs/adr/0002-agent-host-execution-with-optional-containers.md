# 0002 - Agent 默认宿主机直跑，容器为每任务可选后端

日期：2026-08-14
状态：已接受

## 背景

Agent 上执行任务的隔离模型有三条路：

1. **容器优先**（Woodpecker 默认）：每个任务在 Docker/Podman 容器里跑，隔离好、环境一致；但强制构建机装有容器运行时，macOS/Windows 构建机上容器支持弱（Docker Desktop 依赖、Windows 容器镜像生态小），且"单二进制、零依赖部署"的简洁承诺破产。
2. **纯宿主机直跑**：零依赖、最简单；但无隔离，任务环境互相污染，用户心智上会觉得"不如 Woodpecker 安全"。
3. **默认宿主机 + 每任务可选容器**：部署侧保持零依赖，需要隔离/一致环境的 pipeline 可按任务选择容器后端。

## 决策

默认宿主机直跑；容器（v1 以 Docker 为主）作为每个任务的可选后端，在 pipeline 可视化配置里选择。不强制任何容器运行时。

## 后果

- Agent 的"单二进制、全矩阵、零依赖"承诺完整成立（Linux/macOS/Windows × x86_64/aarch64）。
- 宿主机直跑的任务共享构建机环境，需要工作区隔离策略（每次构建独立工作区目录）与缓存 key 设计来缓解污染。
- 每任务可选容器意味着 Agent 要实现两个执行后端（host / container），任务调度模型从第一天起就要抽象"执行环境"概念。
- Windows/macOS 上容器场景降级为"能用但不重点支持"。
