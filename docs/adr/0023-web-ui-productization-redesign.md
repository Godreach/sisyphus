# Web UI 产品化改造

v1 的 web UI 是功能原型，视觉、组件体系、交互体验、信息架构均未达到产品化 release 标准。决定采用渐进式迁移策略，引入 Naive UI 组件库，从 Login/Setup 页面开始逐页面改造。

## 核心决策

- **组件库**：引入 Naive UI，通过 `themeOverrides` 统一配置设计 Token，不自建组件库
- **视觉风格**：GitHub 极简风 + 参考 bk-ci 的卡片式布局、侧栏导航、表格/列表设计、状态标签系统
- **Dark Mode**：跟随系统（`prefers-color-scheme`），不做手动切换
- **响应式**：桌面 + 平板（768px+），不要求手机适配
- **侧栏导航**：重新设计，加入图标（Naive UI 内置 ionicons5）、分组标题、hover 效果
- **旧 CSS**：逐步删除，每迁移一个页面删除对应的 CSS 变量和规则

## 迁移策略

- **节奏**：渐进式迁移，不中断新功能开发
- **起始页**：Login / Setup（最简单，验证主题配置和组件集成）
- **路线图**：制定完整页面迁移顺序，按复杂度递增
- **Pipeline Editor**：保持现有混合交互逻辑，只换视觉风格
- **并行开发**：允许，修改页面时顺带迁移到新组件
